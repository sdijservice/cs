# sdijservice-cs

카카오 상담 로그와 잔디(JANDI) 대화를 **조회하는 전용 웹앱**입니다.

## 한 줄 요약

**조회 화면과 카카오 수집까지 만들어졌고, 배포와 배부가 남았습니다.**
카카오 수집은 사내 직원 누구의 크롬이든 담당할 수 있고, **설치 없이 북마크 하나**로 돕니다
(사내 보안 정책상 확장 프로그램을 설치할 수 없어 이 방식을 씁니다). 특정 개인이나 특정
컴퓨터에 묶이지 않습니다. 아래 "남은 작업"의 4가지를 끝내면 실제로 쓸 수 있습니다.
(잔디 수집은 아직입니다.)

---

## 1. 이게 무엇인가

시대인재 카카오 상담 채널 5개와 잔디 대화방의 기록을 한 화면에서 찾아보는 도구입니다.

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 로그인 | `/login` | 이메일·비밀번호 로그인 |
| 카카오 상담 로그 | `/consults` | 채널·기간·검색어로 상담 찾기, CSV 내려받기 |
| 잔디 대화 | `/jandi` | 방·기간·검색어로 대화 찾기, CSV 내려받기 |
| 수집 설정 | `/collect` | 수집용 북마크 만들기·배부 안내 |

수집 대상 카카오 채널 5개:

| 채널 구분자 | 이름 |
|---|---|
| `_VGAQn` | 마이클래스 |
| `_rcpPG` | LIVE |
| `_TkpPG` | LIVE 기술지원 |
| `_xfxilXn` | 콘텐츠 |
| `_rkbcn` | 통합로그인 |

### 왜 별도 저장소인가

기존 시스템(`sdij-wiki`)은 담당자 **개인 계정**의 인프라 위에 있습니다. 담당자가 퇴사하면
같이 사라집니다. 이 저장소는 **회사 소유 계정**에서 독립적으로 돌아가도록 분리한 것입니다.
그래서 코드는 비슷해 보여도 계정, 주소, 데이터베이스가 전부 다릅니다.

### 일부러 뺀 기능

원본에 있던 실시간 운영 위젯(지금 처리할 대화, 문의량 추세 차트)은 넣지 않았습니다.
운영 분석용이라 유지보수 부담만 늘기 때문입니다. 이 앱의 목적은 "쌓인 데이터를 그대로 보기"
하나입니다.

## 2. 기술 구성

| 항목 | 사용 기술 |

## 3. 내 컴퓨터에서 실행해 보기

```bash
npm install          # 처음 한 번만
cp .env.example .env.local
# .env.local 을 열어 아래 2개 값을 채웁니다 (4장 참고)
npm run dev          # http://localhost:5173 에서 열립니다
```

기타 명령:

```bash
npm run build        # 배포용 빌드 (오류 없이 끝나야 배포 가능)
npm run lint         # 코드 문법 검사
npm test             # 전체 검증 (수집 로직 + 서버 함수)
```

`npm test` 는 두 가지를 돌립니다.

| 무엇 | 파일 | 필요한 것 |
|---|---|---|
| 수집 로직 (유실 방지 규칙 포함) | `test/collector.test.mjs` | Node 만 있으면 됨 |
| 서버 함수 (개인정보 가리기, 저장 순서, 인증) | `test/ingest_test.ts` | Deno (없으면 자동으로 건너뜀) |

서버 함수 테스트에 Deno 가 필요한 이유는 Supabase Edge Functions 가 Deno 위에서 돌기 때문입니다.
설치는 `curl -fsSL https://deno.land/install.sh | sh` 한 줄이고, 안 해도 나머지는 정상입니다.

## 4. 환경변수 (연결 정보)

`.env.local` 파일과 Vercel 프로젝트 설정 **양쪽에 똑같이** 넣어야 합니다.

| 이름 | 값 | 어디서 찾나 |
|---|---|---|
| `VITE_SUPABASE_URL` | `https://<프로젝트ID>.supabase.co` | Supabase 대시보드 > Settings > Data API |
| `VITE_SUPABASE_ANON_KEY` | `sb_publishable_...` 로 시작하는 값 | Supabase 대시보드 > Settings > API Keys > **Publishable key** |

주의할 점 두 가지입니다.

1. **`service_role` 또는 `sb_secret_` 로 시작하는 키는 절대 여기 넣지 마세요.** 그 키는 모든
   데이터를 잠금 없이 열 수 있는 마스터키인데, 이 값들은 웹사이트 소스에 그대로 노출됩니다.
   반드시 공개용(Publishable) 키만 씁니다.
2. Supabase가 최근 키 체계를 바꿨습니다. 화면에 `Legacy anon, service_role API keys` 탭과
   `Publishable and secret API keys` 탭이 따로 있으면 **후자**를 쓰세요. 옛날 키는 프로젝트에
   따라 이미 꺼져 있을 수 있습니다.

## 5. 데이터베이스 준비

`supabase/migrations/0001_init_viewer_schema.sql` 파일을 Supabase 대시보드의 SQL Editor에
붙여넣고 실행하면 필요한 표와 접근 규칙, 수집 키까지 한 번에 만들어집니다.
여러 번 실행해도 안전합니다.

만들어지는 표:

| 표 이름 | 내용 | 브라우저에서 읽기 |
|---|---|---|
| `kakao_partner_chats` | 카카오 상담 대화방 목록 | 로그인한 사람만 |
| `kakao_partner_messages` | 카카오 상담 메시지 본문 | 로그인한 사람만 |
| `jandi_messages` | 잔디 대화 | 로그인한 사람만 |
| `kakao_partner_stream_state` | 수집이 마지막으로 돈 시각 | 로그인한 사람만 |
| `kakao_partner_secrets` | 수집 키 | **아무도 못 읽음** (서버만) |

실행이 끝나면 아래로 **배부할 수집 키**를 확인합니다. 이 값을 `/collect` 화면에 넣습니다.

```sql
select value from public.kakao_partner_secrets where key = 'kakao_ingest_token';
```

### 반드시 확인할 것: 접근 규칙(RLS)

이 앱은 브라우저에서 공개 키로 데이터베이스를 직접 읽습니다. 공개 키는 누구나 볼 수 있는
값이므로, **실제 보호는 전적으로 RLS(Row Level Security, 누가 어떤 행을 볼 수 있는지 정하는
규칙)에 달려 있습니다.** 이 설정을 빠뜨리면 로그인 없이 아무나 전체 상담 내용을 가져갈 수
있습니다.

위 SQL 파일에 규칙이 포함돼 있지만, 실행 후 아래로 **직접 확인**하세요.

```bash
curl "https://<프로젝트ID>.supabase.co/rest/v1/kakao_partner_messages?select=log_id&limit=1" \
     -H "apikey: <공개키>"

curl "https://<프로젝트ID>.supabase.co/rest/v1/kakao_partner_secrets?select=key" \
     -H "apikey: <공개키>"
```

둘 다 빈 배열 `[]` 이 나와야 정상입니다. 데이터가 나오면 규칙이 안 걸린 것이니 즉시 조치해야 합니다.

이 SQL 은 실제 PostgreSQL 16 에 두 번 실행해 다음을 확인했습니다.
로그인 안 한 사람은 상담을 0건 읽고, 로그인한 사람은 읽되 지우지는 못하며,
수집 키는 로그인 여부와 무관하게 아무도 못 읽고, 서버 함수만 읽고 쓸 수 있습니다.
서버 함수가 실제로 만들어 내는 행을 이 표에 그대로 넣어 컬럼이 전부 맞는 것까지 확인했습니다.

### 메시지 표에 외래키가 없는 것은 의도입니다

원본 시스템은 `kakao_partner_messages.chat_id` 에 외래키(FK, 부모 행이 먼저 있어야 자식 행을
넣을 수 있는 규칙)를 걸어 두었고, 그 때문에 **646개 대화방의 메시지가 영구 유실된 사고**가
있었습니다. 처음 보는 대화방의 메시지를 먼저 넣으면 그 묶음이 통째로 실패하는데, 실행 끝에서
"여기까지 받았다" 기록만 최신이 되어 다시는 안 가져오게 됩니다.

여기서는 FK 를 걸지 않았습니다. FK 가 없으면 최악의 경우 대화방 정보가 없는 메시지가 남을 뿐이고
(화면에서 닉네임이 빈칸), FK 가 있으면 최악의 경우 메시지가 사라집니다. **유실이 더 나쁩니다.**
수집기와 서버 함수는 그와 별개로 "대화방 먼저, 메시지 나중" 순서를 지킵니다.

### 주의: 무료 요금제는 활성 프로젝트 2개까지

Supabase 무료 요금제는 **한 사람이 소유한 활성 프로젝트가 2개**로 제한됩니다. 이미 2개를
쓰고 있는 계정에서는 새 프로젝트를 만들거나 정지된 프로젝트를 깨울 수 없습니다.
이 앱은 회사 공용 계정(`sdijservice@gmail.com`)으로 **별도 가입**해 쓰는 것을 전제로 합니다.
그러면 그 계정이 자기 몫의 무료 2개를 새로 받습니다.

### 로그인 계정 만들기

Supabase 대시보드 > Authentication > Users 에서 사용할 사람의 이메일 계정을 추가합니다.
이 앱은 권한 등급을 나누지 않습니다. 로그인만 되면 모든 화면을 볼 수 있습니다.

### 3번 카카오 수집 — 어떻게 만들었나

**카카오는 상담 대화를 내보내는 공식 방법을 제공하지 않습니다.** 그래서 사람이 로그인한 브라우저
세션을 빌려 읽는 것 외에 방법이 없고, 그 일을 할 수 있는 곳은 두 군데뿐입니다.
(1) 크롬 확장 프로그램 (2) 파트너센터 페이지 안에서 도는 스크립트.

원본 시스템은 그 세션을 담당자 한 명의 맥북에서 꺼내 썼습니다. 그 사람이 자리를 비우거나
퇴사하면 수집이 멈춥니다. 실제로 그 문제로 5일간 수집이 중단된 적이 있습니다.
이걸 그대로 옮기면 "특정 개인이 계속 필요한 시스템"을 회사에 남기는 셈이라, 인계가 되지 않습니다.

**사내 보안 정책상 확장 프로그램은 설치할 수 없으므로 (2)를 씁니다.** 설치가 아니라 북마크
하나를 추가하는 방식이라, 직원 PC 에 프로그램이 남지 않습니다.

동작은 이렇습니다.

1. 관리자가 `/collect` 화면에서 수집 키를 넣고 **북마크를 하나 만듭니다**(최초 1회).
2. 파트너센터 권한이 있는 직원이 그 북마크를 자기 브라우저에 추가합니다.
3. `business.kakao.com` 에 로그인한 상태에서 북마크를 누르면, 화면 오른쪽 아래에 상태 창이
   뜨고 바로 수집이 시작됩니다. 그 탭을 열어두면 5분마다 자동으로 계속 모읍니다.

여러 명이 동시에 눌러도 됩니다. 같은 내용을 두 번 넣어도 덮어쓰기라 중복이 생기지 않고,
오히려 한 사람이 자리를 비워도 다른 사람 쪽에서 계속 모입니다.

관련 파일:

| 파일 | 역할 |
|---|---|
| `public/kakao-collect.js` | 실제 수집 동작 (카카오 조회 → 서버 전송 + 상태 창) |
| `src/pages/CollectPage.jsx` | `/collect` 화면. 배부할 북마크를 만들어 준다 |
| `supabase/functions/kakao-ingest/` | 받은 내용을 개인정보 가린 뒤 저장하는 서버 |
| `test/collector.test.mjs` | 유실 방지 규칙 검증 (`npm test`) |

남은 일은 두 가지입니다.

1. **수집 함수 배포 + 수집 키 발급.** `/collect` 화면에 적힌 SQL 을 Supabase SQL Editor 에서
   실행해 키를 만들고, 함수를 배포합니다. 로그인 검사가 아니라 이 키로 인증하므로
   `verify_jwt` 는 꺼야 합니다.

   ```bash
   supabase functions deploy kakao-ingest --no-verify-jwt
   ```

2. **직원들에게 북마크 배부.** `/collect` 화면의 "주소 복사"로 복사해 전달하면 됩니다.

#### 유실을 막는 규칙 (수정 시 주의)

`public/kakao-collect.js` 에는 되돌리면 안 되는 규칙이 하나 있습니다.

**대화 내용을 못 가져온 대화방은, 그 방의 정보를 서버로 보내지 않습니다.** 보내면 서버가
"여기까지 받았다"고 기록해 버려서, 다음 실행이 "변경 없음"으로 판단하고 그 상담을 영영
안 가져옵니다. 원본 시스템에서 이 순서를 어겨 646개 대화방의 메시지가 유실된 적이 있습니다.
`npm test` 가 이 규칙을 검사합니다.

#### 보안상 알아둘 것

- **수집 키는 북마크 주소에 들어가므로 유출될 수 있다고 전제했습니다.** 그래서 이 키로 할 수
  있는 일은 상담 내용 넣기 하나뿐입니다. 읽기·삭제·다른 표 접근은 되지 않습니다. 유출이
  확인되면 `kakao_partner_secrets` 의 값만 새로 만들면 됩니다.
- **개인정보 가리기는 서버가 합니다.** 직원 브라우저에서 도는 코드는 언제든 낡거나 바뀔 수
  있어, 무엇을 저장할지 판단하는 일을 맡기지 않았습니다. 이름·전화번호·이메일·카드번호·
  주민등록번호는 데이터베이스에 저장되기 직전에 가려집니다.
- 카카오 계정의 비밀번호는 어디에도 저장하지 않습니다. 이미 로그인된 세션을 쓸 뿐입니다.

### 5번 잔디 수집

잔디는 아직 만들지 않았습니다. 잔디도 대화 전체를 내보내는 방법이 없어 로그인 세션을 쓰는데,
카카오와 달리 토큰 수명이 약 12시간이라 방식을 따로 정해야 합니다.
지금은 잔디 화면이 비어 있게 됩니다.

### 6번 과거 데이터 이관 시 주의

원본은 90일이 지난 메시지를 데이터베이스에서 빼내 압축 보관합니다(용량 한도 때문). 즉
**원본의 `kakao_partner_messages` 표만 복사하면 90일 이전 기록이 통째로 빠집니다.** 원본의
`kakao-archive` 저장 공간에 있는 압축 파일까지 함께 옮겨야 전체가 됩니다.

## 8. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 화면이 비어 있음 | 데이터베이스에 데이터가 있는지 (7장 참고) |
| 북마크를 눌러도 아무 일이 없음 | `business.kakao.com` 화면에서 눌렀는지. 다른 사이트에서는 동작하지 않음 |
| 상태 창에 "로그인 필요" | 그 탭에서 파트너센터에 다시 로그인한 뒤 "지금 수집" |
| 로그인해도 목록이 안 나옴 | RLS 규칙이 제대로 걸렸는지 (5장) |
| 로그인이 안 됨 | Supabase > Authentication > Users 에 그 계정이 있는지 |
| 배포는 됐는데 흰 화면 | Vercel 환경변수 2개가 들어갔는지 (4장) |
| 조회가 매우 느리거나 오류 | 색인(index)이 만들어졌는지 (5장 SQL 재실행) |

### CSV 내려받기 관련 주의

`src/lib/csvExport.js` 에는 **되돌리면 안 되는 수정**이 들어 있습니다. Supabase는 한 번의
요청으로 돌려주는 행 수를 1000개로 제한합니다(Max Rows 설정). 예전 코드는 "요청한 수보다 적게
왔으면 끝"이라고 판단했는데, 이 제한 때문에 항상 참이 되어 **1000건에서 잘려 나갔습니다.**
실제로 신고된 사고입니다. 그 파일 맨 위 주석에 설명이 있으니 수정 전에 반드시 읽으세요.
